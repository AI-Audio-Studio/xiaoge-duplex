## P1 — 必须修

### [P1-1] affinity.py — create_session 从注册时开始计 state_idle_since，慢启动会话有被误 sweep 的风险
- **状态**: [x] `register()` 中 `state_idle_since` 改为 `0.0`；语义：0.0 = 从未连接/从未断开，不触发 sweep
- **文件**: `examples/voice_agents/gateway/affinity.py:88`
- **问题**: `state_idle_since=self._clock()` 在 `create_session` 中赋值，意味着从槽位注册起即开始倒计时。若浏览器页面加载慢、超过宽限窗才建立 `/ws` 连接，`sweep_expired` 会在 REATTACH 路径可用之前就把该会话标为 CLOSED。
- **修法**: 将 `create_session` 中的初始值改回 `0.0`；`sweep_expired` 对从未有过状态连接的 IDLE 会话改用 `create_time` 字段判断（需在 `Session` 中新增 `create_time: float = field(default_factory=time.monotonic)`），或仅依赖 `on_state_disconnect` 首次调用后才开始计时（保持 `state_idle_since` 初始为 `0.0` 的语义：0.0 = 从未断开过或从未连接过，两者都不应触发 sweep）。

### [P1-2] proxy.py — handle_ws_state pump 段缺 try/finally，外层取消时 on_state_disconnect 不执行
- **状态**: [x] `asyncio.wait` + `up.close()` 包进 `try`，`on_state_disconnect` 移至 `finally`
- **文件**: `examples/voice_agents/gateway/proxy.py:189-196`
- **问题**: `asyncio.wait` → `t.cancel()` → `up.close()` → `on_state_disconnect` 这段没有 `try/finally` 保护。若外层 coroutine 被 aiohttp 因请求超时或连接中止而取消，`CancelledError` 会在 `asyncio.wait` 处抛出，`on_state_disconnect` 不会被调用，`state_idle_since` 停留在 0.0，该槽位永远不会被 sweep 回收。
- **修法**:
  ```python
  try:
      await asyncio.wait({c2u, u2c}, return_when=asyncio.FIRST_COMPLETED)
      for t in (c2u, u2c):
          t.cancel()
      with contextlib.suppress(Exception):
          await up.close()
  finally:
      self._table.on_state_disconnect(sid)
  ```

## P2 — 建议修

### [P2-1] readchar.py — termios.error 捕获范围过宽，会掩盖非 TTY 以外的真实错误
- **状态**: [x] 收窄到 `ENOTTY`/`EINVAL`，其余 re-raise
- **文件**: `livekit-agents/livekit/agents/cli/readchar.py:168`
- **问题**: `except termios.error` 会捕获所有情况，包括 fd 无效、权限不足等真正的错误，导致进入无限等待而非报错。
- **修法**: 收窄到 `ENOTTY`（非 TTY）和 `EINVAL`（某些系统对非 TTY 返回此码），其余 re-raise：
  ```python
  except termios.error as exc:
      import errno as _errno
      if exc.args[0] not in (_errno.ENOTTY, _errno.EINVAL):
          raise
      import threading as _threading
      _threading.Event().wait()
      return ""
  ```

### [P2-2] readchar.py — Event().wait() 无超时，非主线程调用时 SIGTERM 无法中断
- **状态**: [x] 改为带 `timeout=1.0` 的轮询循环，每秒返回一次让信号检查介入
- **文件**: `livekit-agents/livekit/agents/cli/readchar.py:171`
- **问题**: Python 信号处理器只在主线程执行。若 `_posix_readchar` 被非主线程调用，`Event().wait()` 永远阻塞，进程无法通过 SIGTERM 退出。
- **修法**: 确认调用链是否在主线程；若不能保证，改为带超时的轮询：
  ```python
  _stop = _threading.Event()
  while not _stop.is_set():
      _stop.wait(timeout=1.0)
  ```
  或在模块级注册一个全局退出 Event，由信号处理器 `set()` 它。

### [P2-3] manager.py — XIAOGE_AGENT_CONSOLE_ARGS 用 .split() 不支持含空格的参数值
- **状态**: [x] 改为 `shlex.split()`
- **文件**: `examples/voice_agents/poolmgr/manager.py:277`
- **问题**: `.split()` 按空白分词，`XIAOGE_AGENT_CONSOLE_ARGS="--name 'foo bar'"` 会被错误地分成三段。
- **修法**: 改用 `shlex.split()`：
  ```python
  import shlex
  + shlex.split(os.environ.get("XIAOGE_AGENT_CONSOLE_ARGS", ""))
  ```
