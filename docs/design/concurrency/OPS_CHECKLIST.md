# 运维操作清单(并发部署)· dev ↔ ops 交互单

> **这是开发侧与运维侧的唯一交互文件**。背景:目标机**只能经 HTTPS 访问、开发侧不能 SSH 登陆**
> ——凡机上操作(部署、systemd、证书、env、防火墙、kill 测试、磁盘核查)都由**运维**执行,开发侧
> 只能经 HTTPS 驱动负载/读信号。设计与理由见 [DEPLOYMENT.md](DEPLOYMENT.md);规格见
> [CONCURRENCY_DESIGN.md](CONCURRENCY_DESIGN.md)。**本清单力求自足**——运维无需读整套设计即可执行。

## 0. 怎么用这份清单(交互约定)

- 运维经 **GitHub** 读本文件、按序执行。
- **需要运维提供的值** → 直接填到 `【ops 填: ____】`。
- **需要运维执行的操作** → 把 `- [ ]` 改成 `- [x]`,并在其后的 `结果:` 记录(成功/报错原文/实测值)。
- 开发侧**看不到机器**——运维在本文件里的填写/勾选/结果**就是唯一反馈通道**。回填方式:直接编辑本
  文件提 PR,或在对应 PR/issue 评论。
- 有疑问/术语不清 → 见 DEPLOYMENT.md;规格编号(D-xx/M3/R4…)→ CONCURRENCY_DESIGN.md。
- **状态标记**:🔲 待办 · ✅ 完成 · ⛔ 阻塞(缺前置)· ❓ 待对齐(需 dev+ops 商定)。
