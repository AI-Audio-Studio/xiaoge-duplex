# 小歌产品定位

小歌是一款面向家庭场景的全双工语音智能体。它由端侧+云端协同构成,端侧负责实时听觉处理(VAD、唤醒、声纹),云端负责语义理解、对话生成与 TTS 合成。

设计目标有三:第一,低延迟打断——用户随时可以打断 AI 说话;第二,可解释的本地能力——音频不全部上云,关键处理在端侧完成;第三,可热更新的知识库——产品手册、规章制度、FAQ 等内容可独立于模型升级。

---

# 小歌硬件形态

小歌标准硬件包含 4-mic 环形阵列、独立 DSP 前置降噪、ARM Cortex-A55 主控、内置 3W 喇叭与外接 3.5mm 音频输出。麦克风阵列支持 3 米有效拾音,DSP 负责回声消除与稳态噪声抑制。

整机功耗待机 0.8W,工作峰值 4.5W,适合长期常开场景。供电走 5V/2A USB,不内置电池,断电即停。

---

# 小歌硬件规格——麦克风阵列

4 麦环形阵列,麦克风间距 35mm,采样率 16kHz/24bit。阵列几何允许在 3 米半径内实现稳定波束成形与到达方向(DOA)估计,DOA 精度 ±15°。

DSP 输出单通道 PCM 给主控,主控再分发给 STT。当多人同时说话时,波束会跟随能量最强方向,其余方向按 -12dB 衰减。

---

# 小歌硬件规格——喇叭

内置 3W 全频喇叭,频响范围 200Hz–20kHz,适合语音播报与轻量音乐。底噪 < 30dB SPL(A 计权)。

外接 3.5mm 音频输出阻抗 32Ω,可直连有源音箱或耳机。蓝牙 A2DP 不在标准型号内,如需需选配蓝牙模组。

---

# 小歌软件架构——端侧

端侧软件栈基于 LiveKit Agents 框架,核心模块包括:VAD(silero 本地模型)、唤醒词、聆听助手(聆听模式)、断连恢复、本地音乐播放器、关麦门。

端侧全部模块在单进程内运行,通过 asyncio 事件调度。模块间共享 AppRuntime 单例,所有跨模块状态读写都串行在 agent 循环线程。

---

# 小歌软件架构——云端

云端包括三个角色:网关(gateway,WebSocket 反代+apikey 准入)、池管理器(poolmgr,管理多个 agent 进程的生命周期与亲和)、agent 进程(实际承载会话)。

多 agent 进程通过 SO_REUSEPORT 共享监听端口,池管理器按 ready/assigned/spawning 三态调度。冷启动会话被分配到 ready 进程,新进程在后台 spawn 以补足 ready 池。

---

# 小歌全双工设计

全双工是指用户和 AI 可以同时说话、随时打断。小歌实现全双工依赖三层机制:第一层,VAD 实时检测用户开口,触发打断;第二层,出向 TTS 帧与新输入帧解耦,可随时丢弃已排队但未播放的帧;第三层,聆听模式让 AI 主动让出对话,聆听用户完整诉求后再回应。

打断行为受 `overlap_turn_state` 闸门约束:若用户当前这句话压着 AI 播报开口,该轮附和会被拒识,避免和声现象。

---

# 小歌打断实现

用户打断 AI 播报时,系统会:1) 立即停止出向音频播放(浏览器清空 AudioBuffer);2) 取消未消费的 TTS 帧;3) 标记本轮 `user_spoke_over_agent=True`。

打断后 AI 不会立刻回应,而是等待用户完整说完(聆听模式收尾),再生成回应。这避免了"打断→半句话→回应"的破碎体验。

---

# 小歌聆听模式

聆听模式是一种让 AI 主动闭嘴、专注听用户说完的工作模式。触发条件:用户在 AI 播报过程中开口且语义可能较长(如汇报、提问)。

聆听模式由 `listen_ctrl` 管理,有 TTL 守护(默认 8s),超时自动退出。退出条件:用户停顿超过 1.2s,或主动说"好了/可以了"等收尾词。

---

# 小歌音乐播放

小歌内置本地音乐播放器,支持 mp3/wav 解码,通过 16kHz mono int16le PCM 流式推到浏览器。音乐控制通过 LLM function_tool 暴露:`play_music`(播放/换曲)与 `stop_music`(停止)。

起播即让 TTS:音乐首帧会在 LLM 念完播报语后才推出,避免 TTS 与音乐首帧混叠。若 LLM 没念播报语,3 秒兜底 timer 自动起播。

---

# 小歌音乐文件发现

音乐目录扫描缓存默认 60s 刷新一次。匹配策略:1) 精确 stem 命中;2) 子串包含(用户说"声动未来"能命中"声动未来-聚力同行");3) difflib 模糊匹配,阈值 0.5;4) 空或 "random/随机/随便" → 随机一首。

mp3 走 ffmpeg 子进程流式解码,wav 走 wave 标准库。多声道 wav 取左声道;非 16kHz 整数倍率重采样交 ffmpeg 兜底。

---

# 小歌 ASR 后端

小歌支持 FunASR 与 Qwen3-ASR 两套 STT 后端,可在运行时通过 web 面板切换。切换在下一句话生效,不影响当前轮。

FunASR 走 paraformer 流式模型,适合通用中文;Qwen3-ASR 是自部署的 WS 服务,延迟略高但对方言更鲁棒。两个后端都遵守 LiveKit STT 协议,框架自动适配。

---

# 小歌 TTS 后端

小歌支持 cosyvoice 与 Qwen 流式 TTS 两个后端。cosyvoice 韵律自然但需 GPU;Qwen 流式 TTS 部署成本低,首包延迟略高。

TTS 帧通过 WebSocketAudioOutput 推到浏览器,浏览器用 AudioContext + nextPlayTime 队列按时间戳调度。出向缓冲可被 clear_buffer() 清空,用于打断。

---

# 小歌唤醒词

小歌默认唤醒词为"小歌小歌",基于本地 KWS 模型(silero)实现。唤醒后进入 active 态,持续 8s 拾音;若无后续指令,自动退回待机。

唤醒词可在配置文件中替换,但替换后需重新标定误唤醒率(FAR),目标场景 FAR < 0.5 次/小时。

---

# 小歌关麦门

关麦门(mute_gate)是一种强制物理静音机制:用户可通过 web 面板"闭麦"按钮或语音指令"闭麦"触发。触发后麦克风采集被直接短路,即使 VAD 误判也不会上送 STT。

关麦门由用户主动开启,由用户主动关闭,不会因 AI 回应而自动解除。

---

# 小歌隐私与数据

小歌音频处理遵守"端侧优先"原则:VAD、KWS、声纹、回声消除全部在端侧完成,原始音频不上云。上云的只有 VAD 切出的语音段(用于 STT),且会话结束后即从内存清除。

若用户开启"测试录音"功能,原始音频会落盘到本地 `recordings/` 目录,供开发者分析。生产部署默认关闭此功能。

---

# 小歌测试录音

测试录音是开发态功能,开启后会将每轮用户语音与 AI 回应音频同步落盘到 `recordings/<session>/<turn>.wav`。文件含原始麦克风输入与混合后的出向音频两轨。

测试录音会引入额外 I/O 开销,生产环境严禁常开。关闭时只需 `TEST_RECORDER=0` 重启即可。

---

# 小歌会话状态机

单会话状态机由 AppRuntime 集中管理,状态字段包括:agent_loop、job_ctx、session、switchable_stt/tts、mute_gate、ws_audio_input/output、music_player。

状态机保证:web 线程只读不写,所有变更串行在 agent 循环线程(GIL 保证简单赋值原子);未来要多会话时,把单例改为 per-session 实例即可。

---

# 小歌会话断连恢复

当 WebSocket 断连时,会话状态机进入 `listen_exit_pending` 态,等用户停止说话后再做后处理(`listen_enter_aftermath`)。这避免了"断连瞬间还在说话→状态撕裂"。

断连循环终止:5 秒内重连次数超过 3 次会进入退避态,避免打爆网关。

# 小歌音频帧格式

小歌端到端音频帧统一为 16kHz mono int16le,每帧 20ms(320 字节)。LiveKit AudioFrame 标准。所有 STT/TTS/音乐播放器都遵守这一格式。

非 16kHz 源(8k/24k/44.1k/48k)在解码时会被重采样到 16kHz。整数倍率用线性插值,非整数倍率走 ffmpeg 兜底。

# 小歌欢迎语

会话建立后,小歌会主动播报欢迎语:"连接成功,欢迎使用小歌,请开始说话。"

欢迎语由 `say_voice_welcome()` 在 agent 循环线程执行,通过 `session.say(add_to_chat_ctx=False, allow_interruptions=False)` 推送。不进 chat_ctx 是因为欢迎语不算对话内容,不应影响后续上下文。

# 小歌常见问题——网络要求

小歌要求稳定上行带宽 ≥ 2Mbps,延迟 ≤ 100ms。低于此规格会出现 STT 卡顿、TTS 断续。推荐部署在有线或 5GHz Wi-Fi 环境。

2.4GHz Wi-Fi 在微波炉开启或蓝牙密集时会出现明显干扰,不推荐用于生产部署。

---

# 小歌常见问题——多人同时说话

当多人同时说话时,麦克风阵列会跟随能量最强方向,其余方向按 -12dB 衰减。这保证了主说话人的清晰度,但若用户希望"谁都能被听到",需要选配 8-mic 阵列版本。

多人场景下唤醒词唤醒后,小歌默认回应主说话人(能量最强者)。其他人在该轮中即使说话也会被忽略,直到下一轮唤醒。

---

# 小歌常见问题——方言支持

小歌 STT 后端 FunASR/Qwen3-ASR 对普通话、川渝、东北、粤语有较好支持;对闽南语、吴语、客家话支持有限。

方言识别准确率取决于训练数据,如需特定方言场景,可单独训练并替换本地 STT 模型。普通话场景下准确率 ≥ 95%。

---

# 小歌常见问题——电池与供电

小歌标准型号不内置电池,需 5V/2A USB 持续供电。断电会立即停止工作,会话状态丢失。

如需移动场景,可外接 10000mAh 以上的 USB 电源库,续航约 4-6 小时(取决于说话频次)。

---

# 小歌常见问题——音量调节

小歌音量由 web 面板"音量"滑块控制,范围 0-100,默认 60。调到 0 仍会保留极小默认音量,避免用户以为设备故障。

也可通过语音指令"大声点/小声点"调整,每次 ±20。语音指令调音不会反映到面板滑块上,但内部状态会同步。

---

# 小歌常见问题——AI 说错话怎么办

如果 AI 回答有误,用户可直接打断并说"不对,我说的是……",AI 会基于新输入重新生成回应。上一轮错误内容不会进入长期上下文,只影响本轮。

若 AI 频繁说错,可检查:1) 是否 STT 听错(看实时转写);2) 是否 LLM 模型版本旧;3) 是否知识库未更新。

---

# 小歌常见问题——如何升级模型

LLM 模型升级通过修改 `QWEN_MODEL` 环境变量后 `bash xg.sh restart` 生效。模型本体部署在网关侧的 vLLM 服务,与 agent 解耦。

STT/TTS 后端升级需要替换对应的 WS 服务或模型文件,然后切换 `STT_BACKEND`/`TTS_BACKEND` 环境变量。两个后端可独立升级,互不影响。

---

# 小歌常见问题——如何更新知识库

知识库内容更新有两种方式:1) 替换 `data/knowledge/` 下的 Markdown 文件,然后运行 `python -m app.knowledge_index rebuild` 重建索引;2) 通过 API 增量插入单条知识(开发中)。

索引文件位于 `data/knowledge_index/`,含 SQLite(knowledge.db)+向量(npy)。热更新:替换索引文件后,agent 进程下次 query 时自动 reload。

---

# 小歌技术规格——延迟

关键延迟指标(端到端):
- 唤醒响应:≤ 300ms
- VAD 触发:≤ 80ms
- STT 首包:≤ 250ms
- LLM 首 token:≤ 500ms
- TTS 首帧:≤ 400ms
- 感知延迟(felt_latency):≤ 1.2s

以上为 99 分位指标,平均延迟更低。指标由 turn_metrics 日志记录,可从 `.run/` 下查询。

---

# 小歌技术规格——并发

单 agent 进程并发承载 1 个会话(全双工要求独占)。池管理器通过多进程并行扩展:每 CPU 核跑 2 个 agent 进程,8 核机可承载 16 并发会话。

agent 进程冷启动需 4-6s(模型加载),池管理器提前 spawn 保证 ready 池 ≥ 2。

---

# 小歌技术规格——音频采样

音频采样率 16kHz,位深 16-bit,单声道。每帧 20ms = 320 字节 = 160 samples。WebSocket 推送频率 50 帧/秒。

16kHz 是语音识别与音乐播放的折衷:高于 8kHz 电话音质,低于 44.1kHz CD 音质,既保证语音清晰又控制带宽与算力。

---

# 小歌使用场景——客厅

客厅是小歌典型部署场景:常放餐桌或电视柜,4-mic 阵列覆盖 3 米半径。家庭多人场景下,小歌会跟随主说话人方向,适合家庭问答、提醒、播报。

客厅背景噪声(电视、空调)对 silero VAD 影响有限,但建议距离电视 ≥ 1.5 米,避免电视对话被误唤醒。

---

# 小歌使用场景——卧室

卧室部署建议关闭电视联动,仅保留唤醒与播放功能。夜间模式(22:00-7:00)自动降低音量到 30%,且不再主动播报非紧急消息。

卧室场景下应关闭"测试录音",避免音频落盘占用存储。

---

# 小歌使用场景——儿童房

儿童房场景下,小歌可启用"内容过滤"模式:LLM 输出会经过敏感词过滤,不回答成人话题;音乐播放仅限儿童歌单。

儿童模式下唤醒词可改为"小朋友小朋友",降低与成人模式冲突。

---

# 小歌使用场景——办公区

办公区场景下,小歌可作为会议记录助手:实时转写会议内容,生成纪要。多 mic 阵列能跟随不同发言人,但需选配 8-mic 版本以区分相邻座位。

会议场景下应关闭音乐播放与欢迎语,避免干扰。

---

# 小歌开发指南——本地运行

本地运行:`python web_ui_agent.py console`。需要 `.env` 配置 LIVEKIT_URL/API_KEY、QWEN_BASE_URL/API_KEY/MODEL、STT_BACKEND、TTS_BACKEND。

console 模式无 web 面板,音频走本地麦克风与扬声器。适合开发调试,不适合功能展示。

---

# 小歌开发指南——添加新工具

新增 LLM 工具的步骤:1) 在 web_ui_agent.py 的 VoiceAgent 类内加 `@function_tool` 修饰的异步方法;2) 在 docstring 里写清楚触发条件与参数含义,LLM 会基于 docstring 决定是否调用;3) 方法返回字符串,LLM 把它当 function call 结果。

工具返回的字符串是给 LLM 看的"结构化指令",不是给用户直接念的话。LLM 会基于它组织回应话术。

---

# 小歌开发指南——常见坑

常见开发坑:1) 在 web 线程直接修改 agent 状态(会撕裂),必须经 `call_soon_threadsafe`;2) function_tool 中 `await` 长任务会阻塞 LLM,应丢给后台 task;3) AudioFrame 采样率不匹配会无声失败,必须严格 16kHz mono int16le;4) 在 `_play_loop` 里推帧不节流,会把整文件 0.2s 灌进 ws 缓冲导致浏览器播不出来。

---

# 小歌安全——apikey 准入

网关在 `/ws/session` 等路由上做 apikey 准入(模式A):客户端必须在 query string 或 header 带 `apikey=<KEY>`,网关验证后才反代到 agent。

apikey 在网关 `config.toml` 中配置,可热更新(改文件即生效,无需重启)。

---

# 小歌安全——闭麦物理隔离

关麦门是物理级静音:即使 agent 进程恶意或异常想录麦克风,关麦门会在采集层直接短路,音频根本进不到 STT。

这保证了用户对"被监听"的根本性可控:闭麦状态下,设备对用户绝对沉默。

R5.2.2 → R5.3.0 计划:1) 知识库 RAG(query_knowledge 工具);2) 多模态(摄像头输入);3) 跨设备会话迁移。
