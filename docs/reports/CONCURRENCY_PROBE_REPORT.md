# 外部容量摸底报告（并发改造前置，第一轮）

> 2026-07-06。执行 IMPLEMENTATION_PLAN §9 的外部容量摸底(零代码,复用 `AGENT_SCENARIO`
> 回放工具打**线上真机远端**)。目的:在动改造代码前,确认远端依赖(FunASR/LLM/TTS)能否
> 吸收 A1 规划的并发,给 CONCURRENCY_DESIGN Q1-N 一个数据下界。**本轮为第一轮摸底,
> 结论为方向性(directional),非 SLA**(遵 B5:目标机复测前不作对外承诺)。

## 1. 方法

- **负载**:每路 = 一个独立 agent 进程(`web_ui_agent.py console`),`AGENT_SCENARIO` 注入
  一段**真实历史录音**(不同路不同录音)、`AGENT_TIMELINE=1` 落 KPI,各绑独立 `WEB_UI_PORT`。
- **配置对齐服务器形态**:`XIAOGE_KWS_ENABLE_NATIVE=0`(隔离本地 KWS CPU,只测远端);
  主 STT = **FunASR-Stream 2pass**(`STT_BACKEND=funasr-stream`,即线上配置,每路 2 条 FunASR
  流);LLM = Qwen3-4B(10092);TTS = CosyVoice(DashScope)。
- **远端**:FunASR `wss://60.205.197.165:10090`、LLM `https://60.205.197.165:10092`、
  DashScope 云。摸底前 TCP 可达性三处均 OPEN。
- **指标**:各路 `turn_kpis.json` 的 `felt_latency`(体感延迟 = 用户话止→小歌开口)median/p90;
  远端错误(429/503/refused/超时/连接断)计数。
- **阶梯**:N=1(基线)→ N=2 → N=4 并发。判据(P-9):任一 P95(此处用 p90 近似)相对
  基线**退化 >30%** 或**错误率 >1%** → 该档到顶。

  (注,PB-3:CosyVoice 恢复路径调用 0 次**不构成 TTS 并发容量证据**——A1 每进程各一池

- 日志中出现的 "429/503" 经核为**浮点指标数字里的子串**(如 `3.80591…503`),非 HTTP 状态;
  3 处 Traceback 均为 `timeout` 发 SIGTERM 打断 idle 等待的收尾噪声(exit 143),非会话内远端
  失败。**真实远端错误率 = 0**。

## 3. 结论

1. **N≤4 未观察到退化、且远端错误率 0**(felt_latency median ~1900–2200ms,p90 ≤2421ms;
   基线 p90 3833ms 系 TTS 池冷启+样本少的噪声)。(PB-1:四路总样本 ~10 turns、其中一路仅
   1 turn,聚合 latency 在 N=1→4 的**略降是小样本噪声**——这是一个**下界**,不足以确立
   "无退化趋势"这一趋势断言。)
2. **P-9 判据在 N≤4 未触发**(无 >30% 退化、错误率 0)——**在 N≤4 区间**远端未成瓶颈。
   注(PB-2):"4 路会话"对**持久连接**(2N=8 条常驻 FunASR 流)是真并发;对 LLM/TTS 的
   **每轮突发并发**偏弱(1~4 turns 节拍分散,峰值突发很可能 <4),后者正式验证=N3,未做。
3. 对 **Q1-N**:摸底给出**数据下界 N_remote > 4**,且 4 路时远端零压力迹象。结合 D-15
   决策框架(N≤8 → 现 8核16GB+A1 够用),**从远端容量侧支持 A1 规划值 9~10 路**——即
   "远端是否先于本机成为瓶颈"这一最大不确定性,在 N≤4 区间被排除。

## 4. 局限与下一步(诚实标注)

- **样本小、非 SLA**:本轮从 16GB 开发机跑、实时节拍、短录音(每路 1~5 turns),latency
  median 稳定但样本少,属**方向性**结论;正式 N 值仍须**目标机复测**(与 B5 资源复测同批做,
  口径统一)。
- **N≥8 未测**:开发机跑 8 路(8×~1.2GB ≈ 10GB + 8 份判停进程)会让**本机资源**成为混淆
  变量,失去"测远端"的纯度。探到确切天花板(8/10/15)的正确做法 = **在目标服务器上跑
  N=8/10 档**(一举两得:既定 Q1-N,又满足 B5 目标机复测)。
- **DashScope 专项(N3)未做**:N 路"同时说话"的池常驻连接压测 + 商务侧配额书面确认,
  仍待补(本轮 4 路未触发任何 TTS 限流,但未针对性压)。
- **FunASR 2N 流天花板**:N=4 = 8 条 FunASR 流无压力;设计判断"2N 流可能是真天花板"在
  N≤4 未显现,更高并发需目标机验证。

## 5. 给实施前评审 / Q1 拍板的输入

- **可写入 Q1**:远端容量在 **N≤4 区间**无瓶颈,A1 规划 9~10 路**不被远端否决**;确切 N 值待
  目标机 N=8/10 档摸底(与 B5 同批)。
- **严禁越界读作"远端已为 9~10 背书"(PB-4)**:规划 9~10 路 = **18~20 条** FunASR 流,本轮
  只验到 **8 条**(2.3× 差距);GPU 解码是"到点前平稳、到点即塌"的**悬崖型**,N≤4 的平稳
  **不能外推到 9~10**。故**目标机 N=8/10 档摸底 = 设计头号风险(FunASR 2N 流)的门禁验证,
  非可选优化**,须在**对外承诺产能 N / 上线之前**完成。
- **不改变任何已拍板决策**;本报告仅为 Q1-N 的数据支撑,Q1 数值仍开放(现有下界 >4)。

# 评审意见(评审组,2026-07-06,第一轮摸底核查)

> 核查方式:比对报告数字与 `runs/20260706_16*` 原始 `turn_kpis.json`(独立解析,非采信
> 表格)。只读,未改任何工程文件。

**数据真实性 ✅**:N=4 四路 `felt_latency` 的 median_ms/p90_ms 与 §2 表逐一吻合
(164843=1951/2199、164844=2213/2231、164846=1522/1522、164848=2123/2421);10 个
`runs/20260706_16*` 目录俱在。报告数字可信。

**结论采纳为"方向性下界",附四点口径纪律(PB-1~PB-4;均不要求重测,只收紧措辞与用途):**

- **PB-1(措辞收紧)**:N=4 中 164846 仅 **1 turn**(median=p90 是单点),四路总样本
  ~10 turns;且聚合 latency 在 N=1→4 略降,是小样本噪声、非"无退化趋势"的证据。
  准确表述应为"**N≤4 未观察到退化、且远端错误率 0**"(一个下界),而非"无随并发上升
  的退化趋势"(一个趋势断言)——样本不足以确立趋势。§3-1 措辞建议照此弱化。
- **PB-2(并发口径)**:"4 路会话"≠"远端 4 路并发在途请求"。持久型负载(每路 2 条
  **常驻** FunASR 流 → N=4 即 8 条)是真实测到的;但 LLM/TTS 的**每轮突发并发**是否真在
  某刻叠到 4,取决于各路 turn 是否对齐——1~4 turns 且节拍分散时,峰值突发并发很可能 <4。
  故"远端吸收 4 路并发"对**连接数**成立、对**突发并发**偏弱;后者的正式验证 = N3"同时
  说话",本轮未做(报告已诚实标注)。
- **PB-3(观测对象纠正)**:§2"CosyVoice 池未被打穿"落在了错误的池上——A1 每进程各
  自一池(size 3),N=4 = 4 个**互相隔离**的池,本就不存在跨会话池竞争(正是进程隔离的
  设计意图)。该观测只说明"每进程自己的池扛住了自己 1~4 turns"(平凡成立),**不构成**
  TTS 并发容量的证据;真实 TTS 风险是 DashScope **账号级**跨进程并发 = N3,未测。建议
  删去或改写该句,避免读成"TTS 并发已验证"。
- **PB-4(最重要:不越界解读)**:设计 §13 头号风险是"FunASR 2N 流可能是真天花板";
  规划 9~10 路 = **18~20 条** FunASR 流,而本轮只验到 **8 条**(2.3× 差距)。GPU 解码
  这类资源常是"到点前平稳、到点即塌"的悬崖型,**N≤4 的平稳不能外推到 9~10**。因此:
  目标机 N=8/10 档摸底**不是可选优化,是头号风险的门禁验证**,必须在**对外承诺/上线
  产能 N 之前**完成。报告 §5"不被远端否决"的表述正确(它只排除了 N≤4 区间),但请勿
  在下游被读成"远端已为 9~10 背书"。

**裁定**:第一轮摸底**作为方向性下界予以采纳**(远端在 N≤4 无瓶颈、零错误);PB-1/PB-3
两处措辞建议修订,PB-2/PB-4 为用途边界(下游引用时须带"仅 N≤4、连接数口径、非趋势/
非产能背书")。**它解除的是"远端会不会在低并发就先塌"这一疑虑,不解除头号风险在规划 N
的验证义务**——与报告 §4/§5 的诚实标注一致,评审组只是把边界钉得更死。目标机 N=8/10
档(与 B5 同批)为产能定值与上线的前置门禁。
